      How it works: agent architecture
      aquagrid/agents.py
      District agents ×6

      Each broadcasts a WaterRequest with demand, priority and a critical flag.

      Reservoir agents ×2

      Broadcast a WaterOffer of remaining supply and release water when assigned.

      →
      Crisis coordinator

      Collects requests and offers. Serves critical districts first, then runs round-robin in 20-unit chunks so no district starves.

      Asks the network agent for a route each time.

      ⇄
      Network agent

      Runs A* from every reservoir with supply, skipping failed or full pipes. Returns the cheapest RouteProposal and its bottleneck capacity.

      Dispatch updates pipe loads.

      One allocation cycle
      aquagrid/simulator.py
      1. Broadcast. Districts publish requests and reservoirs publish offers.
      2. Route. A* searches with
        f(n) = g(n) + h(n)
        where h is the straight-line distance × the cheapest cost per unit distance, so it never overestimates (admissible).
      3. Allocate. Hospital first, then the other districts in turn, at most min(20, need, path capacity) units per dispatch.
      4. Repeat until no request can be served by any feasible route.
      5. Verify. The engine asserts water conservation and that no pipe exceeds capacity.
